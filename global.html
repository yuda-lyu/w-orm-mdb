castPkFind(find, pk, tp, wi) → {Object}

Description:

  • 改寫查詢條件內之主鍵條件

    註: 輸入為WOrmMdb.mjs之normFind(wsemi之cvOrmFind)回傳之複本, 已在系列條件白名單內(見CLAUDE_rulebook.md之R-WL): 欄位等值、$eq $ne $gt $gte $lt $lte $in $nin、文件層$and $or, 純量為字串、有限數字、布林、Date、null; 本函數在複本上單趟走訪, 每個值只讀一次 註: 主鍵等值類條件(隱含等值、$eq、$ne、$in、$nin)改寫為原列序號欄wi之$in/$nin, 序號集合以佔位陣列置於條件內並列於回傳之slots(各含正規化後之主鍵值vals與佔位陣列is), 呼叫端以Jet判定命中列後以fillPkSlots就地填入, 故命中判定與selectByPk、del等一致, 不經任何近似鍵 註: 主鍵欄只認鍵與pk完全相符者(與reladb之cvFind之嚴格鍵一致), 大小寫或尾端空白不同之近似鍵原樣交cvFind拒收 註: 範圍運算子($gt、$gte、$lt、$lte)留於原欄依記憶體sqlite比較(近似): 界限為有效主鍵值(ok)時以正規化值比較, 其餘(無效、型別不符、不可能存在)原樣留於原欄交cvFind依欄型比較或拒收 (整數主鍵之k > 2.5應命中3、4、5, id < 300個z應為全部; cvFind欄型檢核不接受者如整數主鍵給'abc'、布林、Date則reject), 不改寫為恆假(LW6); 其餘運算子正常不可能到達(cvOrmFind已拒), 若到達則原樣留於原欄, 由cvFind再拒 註: 等值類肯定語境($eq、$in、隱含等值)之無效、型別不符、不可能存在之值不命中(對等值而言不可能等於主鍵欄之值即不命中, 本就正確, 不留null給cvFind); 否定語境($ne、$nin)之無效或型別不符之值(如布林、Date、空字串)一律拋出: 依[無效值不命中]推得之否定為[全部命中], 用於delAll即清空全表, 而此類值多為呼叫端之錯誤; 不可能存在之值於否定語境依其語意為必不相等 註: $ne:null不是無效值而是[非NULL]: 原樣留於原欄交cvFind轉為IS NOT NULL(與非主鍵欄、reladb相同, 令dspec之可攜寫法於主鍵欄亦可用; LW2); 呼叫端若以變數為值, 變數為null時delAll({pk:{$ne:變數}})即刪除全部非NULL主鍵之列(JSDoc已載); {pk:null}、$eq:null維持肯定語境無效值不命中 註: 非運算子物件(如{})視為主鍵值而非條件, 屬無效值, 不得因其無運算子而使主鍵條件消失(cvOrmFind已拒空運算子物件, 此為單獨呼叫本函數時之防線) 註: 主鍵所衍生之序號條件併入同一物件(欄位wi之運算子物件{$in,$nin}), 不增巢狀層(增層會把合法深度放大而於其後cvFind內之再檢核被拒); 同運算子重複者才另以字串鍵{$and:[其餘, ...]}置放; 邏輯陣列之元素若其主鍵條件皆化簡掉(如$ne僅含不可能存在之值)則以恆真之序號條件{wi:{$nin:[-1]}}代替空物件(白名單拒空條件); 不得用sequelize之Symbol Op(cvOrmFind拒Symbol鍵, reladb 1.1.10之cvFind對其reject) 註: 序號條件不產生sequelize之literal(空集合以不存在之序號-1表示) 註: 走訪以Reflect.ownKeys並以defineProperty建構, 不用lodash之each: 具數值length之物件會被當成陣列樣迭代而使條件消失; 非一般物件原樣返回(不可能到達, 交cvFind拒收); 主鍵以外之欄位、運算子與值原樣保留交cvFind檢核與轉譯 註: 第33項批2已移除: $not(欄位層與文件層)與其整體取反、$nor、$regex、$options、Symbol Op、陣列值即$in、RegExp值、頂層$not保留功能

chkFindColKind(attrs, find, pathopt)

Description:

  • 核對條件只引用被model宣告為白名單欄型之欄(R-FLOAT-07, 原LFL5、LFL7)

    白名單欄型: reladb之getColKind分類為str(STRING、TEXT、CHAR、CITEXT、UUID)、int(INTEGER、BIGINT、SMALLINT、MEDIUMINT、TINYINT)、 num(FLOAT、REAL、DOUBLE、DECIMAL、NUMBER)、date(DATE)、dateonly(DATEONLY)、bool(BOOLEAN)者，即Jet欄型可對應者； 其餘(any: TIME、ENUM、JSON、JSONB、BLOB、UUIDV1、UUIDV4、NOW、ARRAY、RANGE、GEOMETRY、GEOGRAPHY、HSTORE、INET、CIDR、MACADDR、TSVECTOR)被條件引用者一律拒收 註: Jet欄型只有文字、數值、日期時間、是否等，沒有上列型別(TIME更無[僅時間]型別)，於model宣告者必為誤宣告或無法對應； reladb之getColKind將其歸any(不換算日期、不檢核值型別)，記憶體過濾表之欄亦不是CITEXT，條件交sqlite比較而與Jet原生不同(真Jet實測): 文字欄分大小寫(delAll({name:{$ne:'APPLE'}})多刪apple)、日期時間欄以文字比較(空白分隔與T不等，$ne多命中)、 TIME之delAll({dt:{$gt:'12:00:00'}})多刪早於12:00之列、ENUM/BLOB宣告於DOUBLE欄時數值依文字序比較。 本套件不改寫非主鍵條件(R-FIND-00)，故改為fail-closed；欄須如實宣告為上列白名單欄型(Jet之DATETIME宣告為DATE，時間值以1899-12-30為日期) 註: 以屬性名或資料庫欄名(attr.field)完全相符解析欄位(與cvFind之嚴格鍵一致，歧義與不存在者留給cvFind拒收)；以getColKind(含type.key後備)判定而不用instanceof(重複安裝兩份sequelize時instanceof為假)； VIRTUAL非資料庫欄，不在此判，交cvFind以unknown column name拒收；路徑格式同cvFind之find.欄名， 訊息固定詞彙(型別名稱取自model之type.key，非條件值；無法辨識者為unknown)而不回顯條件值；不引用該欄者(含空條件)不受影響 註: 須於讀取全表與寫入前呼叫(見WOrmMdb.mjs之findAll)，令拒收時不讀、不寫、不刪

(async) queryMemory(opt, attrs, data, find, keysopt, logSqlopt) → {Promise}

Description:

  • 於記憶體內過濾數據

    因Access之SQL方言不支援$in、$nin等條件，故由Jet取回全部數據後於記憶體sqlite內過濾

    註: 主鍵之等值類條件已由castPkFind改寫為原列序號欄keys.wi之$in/$nin(序號由Jet判定命中列)， 令尾端空白、全半形、平片假名、非ASCII大小寫等變體之命中與selectByPk、insert、save、del一致 註: 條件由w-orm-reladb之cvFind轉譯(非主鍵條件之欄位型別/DATE/嚴格鍵單一擁有者; 運算子白名單與形狀層由wsemi之cvOrmFind檢核, 入口已於WOrmMdb.mjs之normFind完成, cvFind對複本再檢核一次, 冪等)， ctx依其帳本之深引用者接線契約: attrs取過濾表本身之rawAttributes(字串欄為CITEXT、含序號欄)、 dateNoTz為'floating'(Jet之DATETIME為無時區牆上時間: 條件值一律換算為牆上時間分量再作為UTC瞬間, 與主機時區無關)；不傳pk(主鍵等值由Jet判定, 不交sqlite)； reladb 1.1.10起ctx.escape與ctx.dialect已不使用($regex已移除), 故不傳 註: 浮動時間之契約(reladb帳本R14, 本套件帳本R-FLOAT): ①數據側須同進同退——DATE欄之資料值(Jet回傳之牆上時間字串)入表前一律經toFloating換算為同一空間， 混用(條件走floating而數據未換算)為靜默誤命中，故二者同在本函數；②toFloating回傳null者(無法換算)整批拒收，不得以原值或NULL代入 (NULL使該列於範圍條件不命中而IS NULL命中，與要修之誤刪同型)，null/undefined之值不動；③記憶體表之Date為編碼後之浮動時間，不得回傳或回灌為條件 (本函數回傳Jet原列而非記憶體表之Date)；DATE欄之判定與cvFind條件側同用reladb之getColKind(單一擁有者) 註: 修前('local')於負偏移時區主機，Jet本地9999年末之哨兵列(9999-12-31 23:59:59)換算為UTC年10000而使範圍條件結果錯誤、delAll誤刪(原已知限制LF8)，夏令跳過之牆上時刻亦被正規化(原LF4)；浮動時間皆已解 註: 原列序號欄之名稱由呼叫端以genInnerKeys產生(附加亂數)，與castPkFind所用者須相同，且不與使用者之欄位或條件同名 註: 過濾表以原列序號keys.wi為主鍵，主鍵欄不設主鍵與唯一； 結果依序號取回Jet之原列並依Jet回傳序排列，故select之內容即Jet原值(如DATE欄之字串、BOOLEAN欄之true/false)， 與selectByPk相同，而非經sqlite往返轉換之值
