castPkFind(find, pk, tp, wi) → {Object}

Description:

  • 改寫查詢條件內之主鍵條件

    註: 輸入為WOrmMdb.mjs之normFind(wsemi之cvOrmFind)回傳之複本, 已在系列條件白名單內(見CLAUDE_rulebook.md之R-WL): 欄位等值、$eq $ne $gt $gte $lt $lte $in $nin、文件層$and $or, 純量為字串、有限數字、布林、Date、null; 本函數在複本上單趟走訪, 每個值只讀一次 註: 主鍵等值類條件(隱含等值、$eq、$ne、$in、$nin)改寫為原列序號欄wi之$in/$nin, 序號集合以佔位陣列置於條件內並列於回傳之slots(各含正規化後之主鍵值vals與佔位陣列is), 呼叫端以Jet判定命中列後以fillPkSlots就地填入, 故命中判定與selectByPk、del等一致, 不經任何近似鍵 註: 主鍵欄只認鍵與pk完全相符者(與reladb之cvFind之嚴格鍵一致), 大小寫或尾端空白不同之近似鍵原樣交cvFind拒收 註: 範圍運算子($gt、$gte、$lt、$lte)以正規化值留於原欄比對(記憶體sqlite之語意, 為近似); 其餘運算子正常不可能到達(cvOrmFind已拒), 若到達則原樣留於原欄, 由cvFind再拒 註: 肯定語境($eq、$in、隱含等值、範圍運算子)之無效、型別不符、不可能存在之值不命中(範圍運算子亦同, 不留null給cvFind); 否定語境($ne、$nin)之無效或型別不符之值(如null、布林、Date)一律拋出: 依[無效值不命中]推得之否定為[全部命中], 用於delAll即清空全表, 而此類值多為呼叫端之錯誤(如變數為null); 不可能存在之值於否定語境依其語意為必不相等 註: 非運算子物件(如{})視為主鍵值而非條件, 屬無效值, 不得因其無運算子而使主鍵條件消失(cvOrmFind已拒空運算子物件, 此為單獨呼叫本函數時之防線) 註: 主鍵所衍生之序號條件併入同一物件(欄位wi之運算子物件{$in,$nin}), 不增巢狀層(增層會把合法深度放大而於其後cvFind內之再檢核被拒); 同運算子重複者才另以字串鍵{$and:[其餘, ...]}置放; 邏輯陣列之元素若其主鍵條件皆化簡掉(如$ne僅含不可能存在之值)則以恆真之序號條件{wi:{$nin:[-1]}}代替空物件(白名單拒空條件); 不得用sequelize之Symbol Op(cvOrmFind拒Symbol鍵, reladb 1.1.10之cvFind對其reject) 註: 序號條件不產生sequelize之literal(空集合以不存在之序號-1表示) 註: 走訪以Reflect.ownKeys並以defineProperty建構, 不用lodash之each: 具數值length之物件會被當成陣列樣迭代而使條件消失; 非一般物件原樣返回(不可能到達, 交cvFind拒收); 主鍵以外之欄位、運算子與值原樣保留交cvFind檢核與轉譯 註: 第33項批2已移除: $not(欄位層與文件層)與其整體取反、$nor、$regex、$options、Symbol Op、陣列值即$in、RegExp值、頂層$not保留功能

normPk(v, tp) → {Object}

Description:

  • 依主鍵欄型別正規化主鍵值

    註: kind為'ok'(v為正規化後之值)、'invalid'(未給或非有效值, 依T6處置)、'mismatch'(與主鍵欄型別不符)、'cannot'(不可能存在於資料表) 註: 字串類主鍵欄之有限數字以String(v)處置, 與w-serv-orm一致; 數值類主鍵欄僅轉換標準數字字串(String(Number(s))===s), 其餘字串因Jet之INSERT轉型會改變鍵(如'012'存為12)而視為型別不符; 整數類主鍵欄之非整數因Jet會四捨六入五成雙而視為型別不符 註: ±Infinity、NaN、空字串、布林、物件、陣列、Date、BigInt、null、undefined為無效 註: 超過255字元(不計尾端半形空白)之字串於字串類與其他型別(含model未定義主鍵欄而無從得知型別者)皆為不可能存在

(async) queryMemory(opt, attrs, data, find, keysopt) → {Promise}

Description:

  • 於記憶體內過濾數據

    因Access之SQL方言不支援$in、$nin等條件，故由Jet取回全部數據後於記憶體sqlite內過濾

    註: 主鍵之等值類條件已由castPkFind改寫為原列序號欄keys.wi之$in/$nin(序號由Jet判定命中列)， 令尾端空白、全半形、平片假名、非ASCII大小寫等變體之命中與selectByPk、insert、save、del一致 註: 條件由w-orm-reladb之cvFind轉譯(非主鍵條件之欄位型別/DATE/嚴格鍵單一擁有者; 運算子白名單與形狀層由wsemi之cvOrmFind檢核, 入口已於WOrmMdb.mjs之normFind完成, cvFind對複本再檢核一次, 冪等)， ctx依其帳本之深引用者接線契約: attrs取過濾表本身之rawAttributes(字串欄為CITEXT、含序號欄)、 dateNoTz為'local'(Jet之DATETIME無時區, 無時區字串依主機時區)；不傳pk(主鍵等值由Jet判定, 不交sqlite)； reladb 1.1.10起ctx.escape與ctx.dialect已不使用($regex已移除), 故不傳 註: 原列序號欄之名稱由呼叫端以genInnerKeys產生(附加亂數)，與castPkFind所用者須相同，且不與使用者之欄位或條件同名 註: 過濾表以原列序號keys.wi為主鍵，主鍵欄不設主鍵與唯一； 結果依序號取回Jet之原列並依Jet回傳序排列，故select之內容即Jet原值(如DATE欄之字串、BOOLEAN欄之true/false)， 與selectByPk相同，而非經sqlite往返轉換之值
